# 导演约束与候选质量门控

本实现把原有 `WorkflowService` 的导演 → 代码/媒体生成 → 候选审看 → CAS 采用链路接入同一套导演领域结构。它不改变界面布局，不启动第二套独立智能体，也不证明真实模型的生成成功率已经提高。

## 规则来源与范围

规则版本为 `2026-11-06.1`，定义在 `src/director/rules.ts`。每张规则卡包含稳定 ID、版本、原视频链接与时间段、适用范围、要求、失败类别，以及 `tutorial` / `engineering` 来源层级。依据是本仓库提案目录中六条原视频的本地转录、OCR 和关键帧核验；教程中的模型名、精确时序与个别演示成功不是供应商能力保证。

表演使用目标、触发、可见动作、声音动作、结束状态等字段；对白是带说话人和起止时间的事件，保留有意截断、重复、重叠和听者反应。AU 可选，必须附可见动作描述；它不是固定情绪公式，本实现也不承诺模型理解这些标记。产品片、知识讲解、抒情片不强制套悬念六拍。

空间分为 `worldLayouts`、`identityMap` 与当前镜头 `events`。世界锚点是三维坐标；屏幕位置是 0–1 坐标；人物交互关系单独描述。身份映射只允许角色 ID 与资产 ID，禁止夹入站位。事件的 `segmentId` 用来标注空间段；是否真的发生了跨段移动、人物朝向是否正确，仍需查看实际视频。

## 领域 API

`src/director/index.ts` 导出：

- `DIRECTOR_RULESET_VERSION`、`DIRECTOR_RULES`：只读规则与来源。
- `validateDirectorPlan(unknown)`：返回 `{ok, errors, issues, plan?}`；不调用模型。检测版本、重复 ID、引用、时段、坐标范围、静音/对白冲突、重叠标记等；未明确标记的重叠为警告，交由审看。
- `directorShotContext(plan, shotId)`：返回与渲染后端无关的镜头约束，并解析对应全局人物、身份映射、世界布局和故事节拍；包括只在人物关系 from/to 中出现的画外听者。代码分支和媒体编译共享此解析，不把“禁止返回源码”的媒体指令送给代码生成器。
- `compileDirectorShot(plan, shotId)`：返回 `{prompt, ruleSetVersion, referenceAssetIds, audioStrategy}`。分层组织人物、世界、逐拍表演、精确对白、参考与验收条件。
- `patchDirectorPlan(plan, {shotId, changes})`：只替换所选镜头字段，然后重新校验；不改全局身份、世界布局、其他镜头、生产策略或预算。它修改计划，不等于供应商支持几秒钟的局部重拍。

完整类型见 `src/director/contracts.ts`。宿主工具可调用这些纯函数读取规则、检查/编译/局部调整计划，不需要为这些操作另调模型。

## 工作流接入

`WorkflowRequest` 增加可选 `filmKind`、`audioStrategy`、`directorPlan`。`directorPlan` 是通过领域校验的完整结构；提供它时跳过导演模型调用。未提供时，现有导演模型获得字段契约和版本化规则。为兼容简短分镜响应，缺失的表演/空间数组保存为空，不伪造精细指令或检验结果。空工程的结构化分镜使用唯一临时 `shotId`，故事节拍引用相同 ID；建立真实工程镜头后统一重映射，重复临时 ID 在初始化前失败。没有故事引用的旧简短响应仍可不提供临时 ID。最终规范化计划保存在公开的 `WorkflowRecord.directorPlan`。

模型视频与图片调用接收分层编译提示。代码生成得到相同镜头的结构化导演约束，但仍使用原有场景 JSON 合约。模型视频不调用 scene 模型、不读取动画源码、不提交动画源码；空工程只初始化带 `model_video` 来源标记的镜头，不写默认场景源码。视频模型返回图片时直接失败，不降级成静态图或代码。代码模式不允许调用视频模型。图片工作流还须同时具有代码制作权限与生成图片许可，不能在纯模型视频模式中旁路运行代码画面。

所有执行入口、外部请求和采用前均检查统一 `core/production-policy.ts`。工作流保存生产策略指纹；用户改了模式或许可后，旧工作流不能继续生成或采用，须按新策略创建工作流。工作流本身没有签发混合许可的入口。

参考具有 `reference_only` 用途和明确约束维度，不会被自动加入成片。当前工作流上传路径只支持 `imageAssetIds` 中明确授权、已关联镜头的图片，最多 3 张；身份/风格/布局用途会传入媒体能力预检，不支持的参考角色直接拒绝，不会偷换为首帧；并非已经接通所有视频/白模参考接口。空工程会把用户已选图片关联为新镜头的参考。白模视频、音频参考和时间段重拍需要真实供应商能力及端口支持，本模块没有假装实现。

## 声音策略

- `native`：模型视频默认值。候选视频 clip 使用 `audio: keep`，工程开启混音，替换该镜头旧的 voice 配音轨，保留模型对白、呼吸、停顿与环境声。不会调用 TTS。
- `external`：用户明确选择外配音并开启 `narration` 后启用；视频原声为 `mute`，采用明确生成的 voice 音轨。不声称它仍保留原生对白同步表现。
- `silent`：明确静音，视频原声为 `mute`，移除本镜头已有声音片段。含对白事件的静音计划会在领域校验时失败。

`visual: video, narration: true` 必须显式给出 `audioStrategy: external`；不会因为旧 UI 默认勾选配音而悄悄覆盖原声。全局背景音乐仍按工程显式配置处理。原生策略下有对白、声音/呼吸表演或声音硬验收项时，会将 `requiresAudio: true` 传入真实媒体能力预检与文件验证；原生音频能力未知或产物无音轨时不能继续。声轨元数据只能证明存在性；它不能证明对白、抢话或音画同步符合计划。

## 结构化质量报告

`WorkflowRecord.qualityReport` 形状：

```ts
{
  version: 1,
  candidateHash: string,
  decision: 'pass' | 'fail' | 'needs-review',
  checks: [{
    id: string, shotId?: string, category: string,
    severity: 'hard' | 'advisory',
    status: 'pass' | 'fail' | 'unchecked' | 'needs-review',
    message: string, confidence?: number,
    evidence?: [{kind: 'structural' | 'frame' | 'audio' | 'video' | 'human',
                 frame?: number, timeSeconds?: number, sha256?: string, note?: string}]
  }]
}
```

结构检查覆盖本轮所选镜头的生产组成、视频候选无源码、计划时长、素材视频可用长度、参考泄漏和音轨策略。`hard + fail` 阻止采用，用户审看确认不能覆盖它。未在本轮选中的待生成镜头可以继续保留；工作流 complete 表示本批次完成，不代表整片已就绪。整片导出仍检查全主链，不允许缺镜头、来源违规或自动冻结末帧补齐。用户应修正计划或素材后创建新的候选；普通重试保留已有产物，不擅自重生成已完成镜头。

现有视觉模型只收到最多 3 张实际候选关键帧与图片哈希。它必须返回严格 `{visual:{verdict:'pass'|'fail'|'uncertain',confidence:number,message:string}}`。低于 0.8 的信心、非结构化响应或 uncertain 进入人工审看。没有实际帧证据时无论模型声称多确定都保持 unchecked；选中镜头不在主链导致没有可采样帧时，不调用视觉模型或消耗该调用额度，转入实际候选审看。这里只能支持抽样帧视觉结论，不会把模型输出中的音画时序推断升级为通过。

模型视频的全时段动作/连续性、对白与声音默认 `unchecked`；显式验收项在没有对应实际证据时也保持 `unchecked`。没有实际音视频评估端口，因此候选停在 `awaiting-apply`。这不是完整自动审片，静帧也不能证明字幕和实际发声一致。目前没有自动 ASR 对齐、重叠说话检测或全片混音聆听。

可信宿主可调用 `reviewCandidate(id)` 获取已有候选和报告的深拷贝；只允许有候选的 `awaiting-apply` / `failed` 状态，并核对哈希与当前策略。宿主应按真实媒体提供逐镜头播放/听检，准确标注抽样帧或逐镜候选的范围。原始候选和场景源码不能暴露给普通模型工具。

完成实际审看后，可信 UI 可调用：

```ts
apply(workflowId, expectedRevision, {
  candidateHash: record.qualityReport.candidateHash,
  checkIds: ['temporal:shot-id', 'audio:shot-id']
})
```

第三参数只允许来自可信宿主用户操作，不属于 `WorkflowRequest`，模型不能自签。仅当前候选、当前工程版本、真实存在且为 unchecked / needs-review 的检查可确认；证据标为 human。新版本重建候选后旧确认失效，结构化失败不能确认覆盖。`apply(id, revision)` 仍处理版本采用，但不会自动通过未检查条件。

## 持久化、重试与预算

规划、候选、规则版本、质量报告、模型调用时间和素材采用回执随工作流 JSON 持久化。已完成的导演/代码/媒体产物在暂停、重启和重试时复用。候选精确哈希与旧版 CAS 保持一致；重建候选会重新检查。媒体确认失败或工程写入回执丢失时，仍先查已有采用记录，避免重复提交。

`maxTasks` 同时做初步步骤估计和实际外部调用预约；导演、scene、vision、媒体生成和配音都在调用前持久计数，失败也消耗次数。重试不能绕过任务上限，不自动换模式。若预约后进程崩溃但请求尚未发送，可能保守地消耗一次额度；不因此自动多发一次请求。

`maxCost` 仍在任何模型请求前暂停，因为没有可靠的文本、配音和媒体完整预报价。它不是已实现的预付金额硬上限。媒体子账单只有数据完整时显示，整体成本保持未知，不能将部分费用当总账。

## 验证状态

使用本地假模型/假媒体端口的回归测试覆盖：模式拒绝、视频无源码、原声保留、显式外配音、空工程初始化、错误产物类型、短视频硬失败、未检查审看、低信心、确认哈希、预算重试、CAS、暂停恢复和已有候选复用。领域测试覆盖精确对白、重叠例外、坐标层、引用用途、可选 AU、片型和局部计划更新。

没有调用真实模型、上传原视频或测量生产效果。后续真实供应商验收应分别测试多人身份、截断/重复/抢话、词级触发、表情时序、世界/屏幕坐标、参考输入、片长和声轨；保留每一次尝试与预算，不把教程演示当作成功率基线。
