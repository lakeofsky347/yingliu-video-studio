## 同机渲染基准

从 ae05700 的完整 Git 归档运行基线自身的 core/store/renderer/runtime；两端使用同一安装依赖与显式 code_animation 的修正 fixture。每规格各运行一次，顺序为基线→当前；每次导出 60 帧。

| 规格 | 基线导出耗时 | 当前导出耗时 | 单次差值 | 六个抽样帧 RGBA |
| --- | ---: | ---: | ---: | --- |
| 1280 × 720 | 1671.99 ms | 1672.84 ms | +0.05% | 严格一致 |
| 1920 × 1080 | 2001.68 ms | 2115.70 ms | +5.70% | 严格一致 |

四次导出 QA、逆序跳帧和冷启动均通过。严格比较帧为 0、14、29、30、44、59，不能称为所有编码帧逐帧一致。进程树 RSS 的近似采样为 720p 1047.23→1074.19 MiB、1080p 1373.80→1378.03 MiB；含共享页且只有单次观测，本批不宣称速度或内存改善。原始数据与源码哈希在 `artifacts/migration-20261111/bench-{baseline,current,comparison}.json`。

## 数据兼容和回退

工程继续使用 schema v3，没有新增第三方依赖。旧工程缺少导演文档/回执时可直接打开。新增文档随工程内容保存；普通 save/apply 不可修改受保护扩展字段；导演草稿绑定文档版本和 hash，撤销分叉不会被旧草稿静默覆盖。新工程副本清除旧执行请求身份，并将导演批准降为草稿。

API 的 expectedRevision 必填属于兼容性变化：外部脚本先读取工程，提交明确版本，冲突后合并自己的修改。不得通过服务端默补最新版本绕过。完整备份应包含工程目录与 `.studio`；已发生执行的成功/未知回执不能因回退功能而删除。创作撤销保持当前导入请求身份，避免同请求重试撤销用户明确的删除或撤销。
