# yingliu-video-studio 0.8.0

0.8.0 将制作方式隔离、导演约束和 2026-11 的选择性迁移纳入主线，合并基线为 `main@0aa5e3c`。包名仍为 `yingliu-video-studio`，工作台布局保持原样；新增功能放在既有面板中。安装时使用 `yingliu-video-studio@0.8.0` 或同版本的 `yingliu-video-studio-0.8.0.tgz`。

## 本版变化

- **明确制作方式。** 代码动画与模型视频按工程隔离，混合制作按指定镜头授权。配置模型不等于允许使用，生成失败不会自动换一种制作方式补片。模型能力预检、图片上传许可和候选采用检查继续执行。
- **工程导演计划与角色库。** 在「协作制作」中保存角色身份、可见特征、参考图片、音色和镜头要求；草稿有独立版本与内容 hash，由用户批准当前版本。仅制作部分镜头时，不要求上传无关镜头的角色参考。被对白、表演、空间或身份约束引用的角色不能直接删除。
- **导出前本地检查。** 对冻结版本检查结构、素材文件、音轨元数据、字幕文字量和至多 12 个实际抽样帧。结构硬失败阻止导出，黑帧、纯色等启发式结果显示为待查看。每份历史成片保留它自己的报告、版本和检查范围。
- **本地合成音效。** 在「声音与配音」中生成钟声、单音、扫频、噪声冲击、风声和点击六类音效，加入既有音轨后随影片混音导出。参数与种子固定时生成相同 WAV，不调用模型。
- **恢复与并发保护。** 工作流保存独立成功回执和提交状态，不能确认外部提交结果时不会自动重复调用。导入使用固定输入与稳定请求 ID，只对可证明尚未写入的纯追加冲突进行有界重试；并发编辑不会被旧的多文件更新覆盖。
- **预览与编辑稳定性。** 渲染资源按内容固定，旧预览可读取对应依赖；预览收到实际首帧才就绪，超时可重新加载。旧工程的异步任务或候选预览不会进入新工程面板。导演草稿按工程保留，并检查版本及内容基线；损坏草稿保留原始数据并提示恢复。

本版也包含 Windows 新导入文件同步权限修复、导出失败后的资源清理，以及跨平台回归的改进。0.7.0 的静态缩略图与逐帧捕获优化继续保留，其历史性能数据见 [渲染说明](RENDERING.md)。

## 升级前后

1. **备份整个工程目录，包括隐藏的 `.studio/`。** 其中保存历史版本、任务和导入回执；不要为排障直接删除回执。尚未保存的源码与导演编辑草稿位于客户端本地存储，应先保存或另行备份。
2. **使用支持 schema v3 的插件继续编辑。** 0.8.0 的新工程为 schema v3；读取旧 v1/v2 工程时保留稳定 ID、源码、素材和历史内容，并把制作方式置为待确认。首次继续制作前，在工作台「制作要求」中明确选择代码动画、模型视频或允许的混合范围。
3. **更新外部写入调用。** 修改已有工程内容的 RPC 必须先读取当前 `revision`，再传 `expectedRevision`。缺少版本返回 `REVISION_REQUIRED`，版本过期返回 `REVISION_CONFLICT`；应重新读取后合并修改，不能直接用最新版本号重放一份旧工程。具体入口和可选版本的检查接口见 [API 兼容变更](API.md#2026-11-选择性迁移接口)。
4. **重试同一导入时复用请求 ID。** `import`、音频导入和本地音效支持稳定 `requestId`；更换输入内容应换 ID。多文件工具会保留已完成项目，在并发版本变化时停止余下更新。替换配音、模型调用和未知外部提交不属于纯追加自动重试。
5. **分别保留内容批准与制作许可。** 保存导演计划会产生草稿；计划批准不会启动生成，也不授予模型付费、图片上传或混合制作权限。需要实际播放审看的候选仍须通过原有的人审步骤。

工程 schema v3、会话关系 `sessions.json` 的 v2 索引、导演文档自身的 schemaVersion=1 是不同数据结构的版本。不要将这些数字当作同一版本；也不要让旧插件覆盖写入已升级工程及其新增扩展字段。复制工程会清除执行请求身份，并将导演批准降为草稿。

## 能力与验证边界

本地抽样检查不等于完整成片验收：完整动作、口型、实际听感和字幕边界没有因此自动通过。未知费用仍为未知，不能当作免费。本版没有迁入独立应用的聊天 Agent 或 Electron/Tauri 外壳；累计费用账本、费用试算、尾帧衔接、显式配音对齐、一致性复核及后续供应商扩展（M08–M12）不在本版范围内。
